## Papers and evaluation design

All four supplied arXiv IDs resolve to the intended work.

- [LEANN: A Low-Storage Vector Index, v2](https://arxiv.org/abs/2506.08276v2). Its mechanism recomputes embeddings and prunes/compresses proximity graphs. The paper reports substantial storage reductions on its own workloads. Those results are neither RAVEL measurements nor proof that recomputation is fastest on a different device. Count metadata, source-text copies and caches as well as vector bytes.
- [ContextBench, v3](https://arxiv.org/abs/2602.05892v3). The authors evaluate retrieval during issue resolution, with human-annotated context at file, block and line granularity. This motivates reporting useful context and token consumption separately from patch success. [Dataset](https://huggingface.co/datasets/Contextbench/ContextBench), [evaluation repository](https://github.com/EuniAI/ContextBench). Use frozen pre-fix repository revisions; an unexecuted adapter is not a benchmark result.
- [Agent Retrieval Bench, v1](https://arxiv.org/abs/2607.24882v1). Workflow-derived file retrieval includes related tests, extra review context, root-cause code, change ripple and no-gold cases. Its results show different winners for different tasks and budgets. [Evaluator](https://github.com/eyuansu62/agent-retrieval-bench), [dataset](https://huggingface.co/datasets/eyuansu71/agent_retrieval_bench). Keep natural no-gold and wrong-repository controls separate. Match the official all-files candidate set and token packing before comparing leaderboard scores. The current evaluator includes October fixes, so reruns need a pinned evaluator commit.
- [CORE-Bench, v3](https://arxiv.org/abs/2606.11864v3). It distinguishes code understanding, edit localization and broader context, exposing the gap between snippet similarity and repository work. [Data](https://huggingface.co/datasets/zhangfw123/CORE-Bench), [evaluation](https://github.com/zhangfw123/CORE-Bench-Eval). Its data card specifies CC-BY-NC-SA-4.0, independent of RAVEL's software license. The generic dataset viewer showed a schema error during inspection; this does not establish that the raw dataset files are unavailable.

No paper's published leaderboard is a matched-hardware head-to-head result for this release. A developer-authored small suite can test regressions and tradeoffs, but cannot establish generalization to these full benchmarks or downstream coding-task success.

## Relevant prior art beyond the initial list

- [SelRoute (April 2026)](https://arxiv.org/abs/2604.02431): query-type routing among lexical, semantic, hybrid and enriched memory retrieval. It reports cross-validation and a reasoning-heavy failure case. Routing alone is not novel; RAVEL needs to evaluate the joint effects of retrieval depth, persistent embedding budget, cache admission and delivered context budget.
- [Adaptive-RAG (NAACL 2024)](https://arxiv.org/abs/2403.14403): a learned complexity classifier chooses between retrieval/generation strategies. A learned router must earn its extra complexity against simple deterministic rules on held-out data.
- [Matryoshka Representation Learning](https://arxiv.org/abs/2205.13147): nested representations can trade dimensions for retrieval cost when the model was trained for this property. Arbitrarily truncating ordinary embeddings is not equivalent. Int8 quantization is an established compression baseline, not a new algorithm.
- [SQLite FTS5](https://sqlite.org/fts5.html): proven full-text indexing and BM25 avoid a custom storage engine. Contentless/external-content modes reduce duplicate storage but require correct update/delete handling. A contentless index still leaks indexed vocabulary and is not encryption.

## RAVEL's testable contribution

The intended contribution is a compact systems design that coordinates query routing, retrieval depth, persistent vector admission/eviction and context packing under explicit budgets, while validating source freshness before delivery. It is an engineering contribution with an experimental hypothesis, not a claim to have invented hybrid search, adaptive RAG, quantization, caching, ASTs or MCP.

A defensible result requires an ablation against lexical-only, fixed hybrid, all-vector and no-cache policies; cold and warm timings; index plus cache size; retrieval ranking/recall; and context cost. Compare a lightweight learned selector against deterministic heuristics with disjoint training/evaluation queries or repository groups. Keep a learned policy optional when it loses or has insufficient evidence. Report where a smaller index recomputes more slowly or misses semantically distant matches. Do not advertise universal superiority or claim that a small local suite proves better coding-agent outcomes.
